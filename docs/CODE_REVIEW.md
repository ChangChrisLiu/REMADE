# 代码审查记录

审查日期：2026-10-28。范围包括原项目自有的 39 个 Python 文件（7,820 行）、原 shell 调用链、全部文件/资产清单、参考项目架构，以及新 `remade/` 主线。所有原 Python 源码做了 AST 解析；第三方 ROS 驱动按架构和接口检查，没有宣称逐行验证其所有 C++、launch 和配置文件。

审查采用一次独立的基线检查和一次独立的新主线检查。运行验证仅针对 `tests/`，没有导入历史设备脚本、加载模型或连接硬件。

## 主线问题与处理

| 原问题 | 影响 | 新主线处理 |
|---|---|---|
| 单次 `recv(1108)` 后直接解包 | TCP 分片可导致数据不完整 | 按报文头长度收齐，校验大小、断连和数值 |
| 每轮状态读取重复建连接 | 连接开销、未消费的数据流 | 复用控制/状态 socket，读取并排空旧状态包 |
| 连接与运动等待无超时 | 设备异常时可能一直等待 | 有限 socket 超时与运动截止时间 |
| 运动异常等 UI 清理才停止 | 慢推理会推迟 stopl | 工作线程在运动异常路径立即尽力发送 stopl，保留原异常 |
| 发送下降指令后 10 ms 就释放真空 | 未到放置高度便可能掉落 | `arm.move` 确认到位后才 `vacuum.off` |
| shell/Modbus 错误被忽略 | 真空控制失败仍继续 | 检查连接与 Modbus 应答，错误向主循环传播 |
| `pkill socat` 清理所有桥接 | 影响无关设备会话 | 只终止自己持有的子进程 |
| 每次采图都重启 pipeline | 浪费初始化、资源生命周期不清 | 单 pipeline 持续采集、显式关闭 |
| 每帧重新加载模型 | 推理前重复加载权重 | 单 Detector 持有单模型 |
| 单次拍照且抓取阻塞画面 | 不满足实时监测 | 主线程持续图像处理，单工作线程分拣 |
| 整批使用旧图像目标 | 堆叠层/工件变化后目标过期 | 每件归位后清空帧缓存并重新观察 |
| 姿态数组直接引用后改 z | 改写共享工位/目标 | 明确复制位姿数组 |
| 零旋转/π 旋转奇异、欧拉角绕回 | 合法姿态可能产生 NaN 或错误等待 | 稳定 Rodrigues 和矩阵角距离 |
| 顶层连接机器人 | 测试/导入具有设备副作用 | 可导入模块；`--sort` 才创建机器人流程 |
| 置信度/路径/IP 分散 | 难以追踪运行配置 | 命令行 + 集中配置 + 项目根路径解析 |
| 替换模型后类别 ID 含义可能变化 | 错误分拣路由 | 分拣启动时核对模型类别 ID 与名称 |

独立审查还发现监测测试依赖“第 2 帧时线程已启动”的调度假设；测试现已使用真实 READY 状态与事件同步，避免时序性误报。

发布后的 Linux CI 还发现源码索引按 `Path` 默认规则排序，在 Windows 与 Linux 上顺序不同。生成器已改成按 POSIX 相对路径字符串排序，并增加大小写文件名的跨平台回归测试。

本地最终验证：29 项自动化测试、123 个 Python 文件语法解析、461 个原文件迁移校验、16 个模型/轨迹/样例资产记录、文档链接与索引检查。完整依赖执行过 pip dry-run 解析，但未在此环境安装和运行模型。远端结果见 [GitHub Actions](https://github.com/ChangChrisLiu/REMADE/actions/workflows/checks.yml)。

## 历史代码保留的问题

这些问题不进入维护主线，但为了保留研究过程，没有修改归档文件：

- `legacy/scripts/runwithpath.py`、`standardpickup.py` 的 `move_to_joint_sequence` 对共享轨迹 `row.extend(...)`。第二次重复使用时，路点会从 6/9 个字段继续增长，变成无效格式。
- `legacy/scripts/REMADETEST.py` 同时连接实验 IP 和 localhost RTDE，环境假设不一致。
- `legacy/scripts/Fulltest.py`、`ootest1.py` 的平移向量形状与二维索引期望不匹配。
- `legacy/scripts/util.py` 在零旋转和半周旋转附近处理不完整。
- `legacy/gripper_tests/test111.py` 把需要 channel 参数的方法定义为 property，访问时会出错。
- `legacy/scripts/rtde.py` 的旧 Python 2/3 文本/bytes 处理不一致，不作为新通信库沿用。
- `legacy/scripts/imagete.py` 等包含原机器绝对路径；归档后相对路径也需按实际运行目录调整。
- 多个原脚本保留高速度、固定 IP、固定 TCP、固定工位和顶层设备操作，不能根据文件名中的 test 判断可以离线运行。

## 验证边界与仍需实机确认的事项

1. 标定矩阵、TCP、相机安装、拾取高度、负 z 与工位净空对应原实验台；没有重新测量或碰撞检查。
2. 新默认速度 0.2 m/s、加速度 0.5 m/s²、真空 60% 与旧 DEMO 部分参数不同，需要实验台验证。
3. Modbus 应答不是吸附成功证明；尚无压力闭环、抓取失败重试或掉落检测。
4. 30003 状态包仍基于原控制器布局中 444:492 的 TCP 字段；需要在实际 UR 固件上核对。
5. RealSense 1920×1080/30 FPS、USB 稳定性、GUI 响应时间和 GPU 推理性能未在当前环境测量。
6. 主流程没有集成翻转、在线避障、轨迹规划、切割/冷却/摆锤联锁，也没有把这些功能伪装为可用。
7. 模型与候选依赖栈未在实验环境重现；类别识别性能应单独评估。

离线检查命令、源代码清单和资产 hash 可用于持续集成，但不能替代实机验收。后续若扩展到生产部署，应将上述事项按实际工位逐个完成。
